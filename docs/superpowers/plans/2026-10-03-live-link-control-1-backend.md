# Live link Control — Plan 1 of 3: Backend (nodeterm-server) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a live link be created with no end time (`ttlSeconds: 0` → `expiresAt: null`), and stop an unlimited link from outliving its owner's Pro by more than a day.

**Architecture:** A migration makes `watch_links.expires_at` nullable. Every query and rule that reads `expires_at` learns that NULL means "live until stopped". The host-token route, which already runs for every listener the desktop opens, checks the license's liveness for an unlimited link at most once per 24 h per license (in memory), reusing the create route's `licenseLiveness`.

**Tech Stack:** Hono 4.12, zod, drizzle-orm 0.36 + drizzle-kit (Postgres; pglite in tests), vitest 2.1, Node `crypto`.

**Spec:** `/root/nodeterm/wtshare/docs/superpowers/specs/2026-10-03-live-link-control-design.md` §3 and §8. Base spec: `/root/nodeterm/wtshare/docs/superpowers/specs/2026-09-28-live-share-link-design.md`.

**Plans in this series:** 1 = this (backend), 2 = `2026-10-03-live-link-control-2-desktop.md`, 3 = `2026-10-03-live-link-control-3-web.md`. This plan merges and deploys FIRST: an old desktop never sends `0`, and an old backend answers `0` with `400 bad_ttl`, which the new desktop shows as "Unlimited links need a newer server".

**Repo:** `/root/nodeterm-server-watch` is a worktree of eneskirca/nodeterm-server. Create a NEW branch `feat/watch-links-unlimited` from `origin/main` (currently `a4f7d9c`; the local `main` there is behind — do not base on it). Never push `main`.

## Global Constraints

- Wire value for Unlimited: `ttlSeconds: 0`. The create response then carries `"expiresAt": null` (JSON null, not absent, not 0).
- `ttlSeconds: 0` is granted only when **no** `WATCH_LINK_MAX_TTL_SECONDS` cap is configured (`deps.maxTtlSeconds` undefined or ≤ 0). With a cap configured it is clamped to the largest allowed standard length, exactly like an over-cap request.
- The standard lengths stay `{900, 3600, 28800, 86400}`; any other value (negative, fractional, 1) is still `400 bad_ttl` / `bad_request` as today.
- NULL `expires_at` = live, everywhere: `linkState`, the per-license active count, revoke-all, status, host-token, join.
- The 7-day purge never deletes a NULL row (`expires_at < x` is false for NULL; a test pins it).
- Unlimited host-token liveness: `live` cached 24 h per license; `unknown` (keygen unreachable) **allows** the mint and is cached 10 min; `dead` answers `402 {"error":"not_entitled"}` and is never cached. Finite links keep the rule that a host-token mint never calls keygen.
- Never log tokens, entitlements, license ids or bodies.

## Review Focus

1. **A row created by the old code path (non-null `expires_at`) after the migration** → behaves exactly as before; the migration must not touch existing rows.
2. **Revoke-all with a mix of finite, expired and unlimited rows** → finite live and unlimited rows are stopped; expired rows keep reporting `expired` (their `revoked_at` stays NULL).
3. **A keygen outage while an unlimited link reconnects** → host-token answers 200 (fail open, the spec's choice) and keygen is not asked again for 10 minutes even if the desktop reconnects many times.
4. **An entitlement without a string `deviceId` on an unlimited host-token** → 402, never a keygen call with `undefined`.
5. **Two licenses sharing the cache** → a live verdict for license A never answers for license B.

```ts
import { and, eq, gt, isNull, lt, or } from 'drizzle-orm'

export const WATCH_LINK_TTLS = [900, 3600, 28800, 86400] as const
/** The wire value for "no end time": the link lives until it is stopped. */
export const UNLIMITED_TTL = 0

export function linkState(row: Pick<LinkRow, 'revokedAt' | 'expiresAt'>, nowMs: number = Date.now()): LinkState {
  if (row.revokedAt) return 'revoked'
  // NULL = no end time. Expiry is inclusive: a link whose instant has come is over.
  if (row.expiresAt !== null && row.expiresAt.getTime() <= nowMs) return 'expired'
  return 'live'
}
```

Inside `registerWatchLinks`:

```ts
  const capConfigured = typeof deps.maxTtlSeconds === 'number' && deps.maxTtlSeconds > 0
  const maxTtl = capConfigured ? (deps.maxTtlSeconds as number) : 86400
  const allowedTtls: readonly number[] = WATCH_LINK_TTLS.filter((t) => t <= maxTtl)

  /** Seconds granted, `null` for "no end time", or `undefined` to refuse. */
  function grantedTtl(requested: number): number | null | undefined {
    if (requested === UNLIMITED_TTL) {
      if (!capConfigured) return null
      return allowedTtls.length === 0 ? undefined : Math.max(...allowedTtls)
    }
    if (!(WATCH_LINK_TTLS as readonly number[]).includes(requested)) return undefined
    if (allowedTtls.length === 0) return undefined
    return requested <= maxTtl ? requested : Math.max(...allowedTtls)
  }

  /** A row that is not over by time: no end time, or one still ahead. */
  const notExpired = (at: Date) => or(isNull(watchLinks.expiresAt), gt(watchLinks.expiresAt, at))
```

```ts
  const now = deps.now ?? Date.now
  /** licenseId → the last liveness verdict that may stand in for a fresh one, and when it was taken. */
  const unlimitedLiveness = new Map<string, { verdict: 'live' | 'unknown'; at: number }>()
  async function unlimitedMayMint(ent: EntitlementPayload): Promise<boolean> {
    if (typeof ent.deviceId !== 'string') return false
    const hit = unlimitedLiveness.get(ent.licenseId)
    const t = now()
    if (hit) {
      const ttl = hit.verdict === 'live' ? UNLIMITED_LIVENESS_LIVE_MS : UNLIMITED_LIVENESS_UNKNOWN_MS
      if (t - hit.at < ttl) return true
    }
    const verdict = await licenseLiveness(ent)
    if (verdict === 'dead') {
      unlimitedLiveness.delete(ent.licenseId)
      return false
    }
    unlimitedLiveness.set(ent.licenseId, { verdict, at: t })
    return true
  }
```
